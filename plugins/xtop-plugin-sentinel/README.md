<h1>Sentinel Plugin</h1>

<p>Sentinel is an AI-aware system monitoring and management plugin for xtop. It exposes system metrics, process information, and configuration through a simple command interface designed to be consumed by AI agents (including LLM-based assistants).</p>

<p>It also includes a built-in <strong>MCP server</strong> (<code>xtop mcp</code>) that exposes all commands as MCP tools for seamless AI integration.</p>

<hr>

<h2 id="features">Features</h2>

<ul>
  <li>Read system summary (CPU, memory, disks, network, uptime) as JSON</li>
  <li>Query top processes with full details and optional regex filter</li>
  <li>Search processes by regex on name, cmd, user, or state fields</li>
  <li>Kill processes safely by PID</li>
  <li>Get and set alert thresholds</li>
  <li>Read and update xtop configuration (theme, layout, interval)</li>
  <li>Automatic process anomaly detection (CPU spikes, root processes)</li>
  <li>Custom TUI widget for visual status</li>
  <li>MCP server over stdio for AI tool integration</li>
</ul>

<hr>

<h2 id="command-interface">Command Interface</h2>

<p>All interaction happens through a single entry point:</p>

<pre><code>plugin.execute(ctx, "&lt;action&gt;", "&lt;params&gt;") -&gt; Result&lt;String, PluginError&gt;</code></pre>

<p>The response is always a JSON string, making it easy for any AI or script to parse.</p>

<h3 id="processessearch">processes.search</h3>

<p>Search processes using a regex pattern. Supports filtering on specific fields.</p>

<table>
  <thead><tr><th>Params</th><th>Response</th></tr></thead>
  <tbody>
    <tr><td><code>"pattern"</code> or <code>"pattern,fields=f1,f2"</code></td><td>JSON array of matching processes</td></tr>
  </tbody>
</table>

<p>Supported fields: <code>name</code>, <code>cmd</code>, <code>user</code>, <code>state</code>. Default: <code>name</code> only.</p>

<p>Examples:</p>

<pre><code># Search by name
processes.search("firefox")

# Regex on name
processes.search("/python|node/")

# Regex on name AND cmd
processes.search("/systemd/,fields=name,cmd")

# Filter by user
processes.search("/^0$/,fields=user")</code></pre>

<p>Response:</p>

<pre><code>[{"pid": 1234, "name": "firefox", "cpu": 45.2, "mem_bytes": 1048576000, "state": "Running", "user": "1000", "cmd": "/usr/lib/firefox/firefox"}]</code></pre>

<h3 id="processestop-regex">processes.top (with filter)</h3>

<p>Top processes with optional regex filter on name or cmd:</p>

<pre><code># Top 5 processes matching the pattern
processes.top("5,filter=/firefox/")</code></pre>

<h2 id="tui-widget">TUI Widget</h2>

<p>Sentinel registers a widget named <code>"sentinel"</code>. Include it in any custom layout by referencing it in a JSONC layout file:</p>

<pre><code>{
    "name": "monitor",
    "root": {
        "direction": "vertical",
        "areas": [
            { "widget": "header", "size": 3 },
            { "widget": "sentinel", "size": 6 },
            { "widget": "processes", "size": "*" }
        ]
    }
}</code></pre>

<p>The widget renders a bordered panel with dark background and accent-colored title showing the agent status and a help hint.</p>

<h2 id="mcp-server">MCP Server</h2>

<p>Sentinel includes a built-in MCP server that exposes all commands as MCP tools.
Run it with:</p>

<pre><code>xtop mcp</code></pre>

<p>The server speaks JSON-RPC 2.0 over stdin/stdout (standard MCP transport).
Any MCP-compatible AI can connect:</p>

<h3>Claude Desktop</h3>

<pre><code>{
  "mcpServers": {
    "xtop": {
      "command": "xtop",
      "args": ["mcp"]
    }
  }
}</code></pre>

<h3>Interactive testing</h3>

<pre><code># Call system_summary
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"system_summary","arguments":{}}}' | xtop mcp

# Search processes with regex
echo '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"processes_search","arguments":{"pattern":"/firefox|chrome/"}}}' | xtop mcp

# Kill a process
echo '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"process_kill","arguments":{"pid":1234}}}' | xtop mcp</code></pre>

<h2 id="process-analysis">Process Analysis</h2>

<p>Sentinel includes a heuristic analyzer that runs every 10 ticks (~10 seconds):</p>

<ul>
  <li>Flags processes with CPU usage above 80%</li>
  <li>Flags root-owned processes with CPU above 50%</li>
  <li>Collects up to 20 alerts per cycle</li>
  <li>Alerts are exposed via <code>alerts.status</code> command</li>
</ul>

<p>The analysis is basic by design. Deeper security heuristics are delegated to domain experts.</p>

<h2 id="ai-integration">AI Integration</h2>

<p>Sentinel exposes two interfaces for AI agents:</p>

<h3>Direct execute() (for embedded agents)</h3>
<p>Callable from within xtop's plugin system via <code>PluginManager::execute("sentinel", action, params)</code>.</p>

<h3>MCP protocol (for external AI)</h3>
<p>Run <code>xtop mcp</code> and configure your AI assistant's MCP client to connect.
The AI sees all Sentinel tools as callable functions with typed parameters.</p>

<p>Typical AI workflow via MCP:</p>

<ol>
  <li>AI calls <code>system_summary</code> to get a health overview</li>
  <li>AI calls <code>processes_top</code> with optional regex filter</li>
  <li>If suspicious, AI calls <code>process_info</code> for details</li>
  <li>AI may call <code>process_kill</code> to terminate</li>
  <li>AI calls <code>alerts_status</code> periodically for anomalies</li>
</ol>
